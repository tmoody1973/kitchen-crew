Mise — App Map

A take-home guide to where things live in the code. A snapshot of the finished build; it can drift as the app changes.

What Mise is

Mise keeps a family's weekly groceries under budget. A chat "crew" (Claude) plans dinners priced with real Kroger prices, the week board schedules them, the shopping list fills itself, and a tally shows what's left as you type what you actually paid.

  • Screens

    Next.js pages in app/: Plan, Week, List, Pantry, Recipes, Budget.

  • Data

    Convex in convex/: weeks, list items, dinners, recipes. Screens subscribe to it and redraw when it changes.

  • Rules and math

    Plain functions in lib/: the tally, plan pricing, barcodes, grouping. Most have tests next to them.

  • Outside services

    Kroger (prices), Claude (crew, recipe reading, tags), YouTube, TinyFish, Instacart — called only from server routes in app/api/.

One action, followed through the code

You type what you paid for an item; the tally at the top changes. There is no "save" button and no refresh: the number travels to the database, and every screen watching that data redraws.

1

The paid box

components/ListRow.tsx · search async function savePaid

When you leave the box (or press Enter), savePaid turns your text into a number and calls the setPaid mutation with this row's id. Leaving the box empty clears the amount.

2

Saving it

convex/listItems.ts · search export const setPaid

Runs on Convex's servers: checkAmount rejects nonsense amounts, ownItem makes sure the row belongs to the signed-in person, then ctx.db.patch writes paid onto the row.

The whole function
export const setPaid = mutation({
  args: { id: v.id("listItems"), paid: v.optional(v.number()) },
  handler: async (ctx, { id, paid }) => {
    checkAmount(paid, "Paid amount");
    await ownItem(ctx, id);
    await ctx.db.patch(id, { paid });
  },
});
3

The tally redraws

components/TallyHeader.tsx · search useQuery(api.listItems.mine → lib/tally.ts · export function computeTally

The header is subscribed to the week's list. When the row changes, Convex sends the new list, and computeTally (plus computeSplitTally for Dinners/Extras) recomputes what's spent and what's left. The "Under budget this week!" line comes from the same file.

A practice to reuse

Test a rule against real data, not just the examples you imagined.

When Mise reads recipes from YouTube, it has to pick the written-recipe link out of descriptions full of shop, sponsor and social links. The first version of the filter in lib/recipes/links.ts passed its six tests. Running it over all 86 real descriptions in the playlist then exposed leaks the tests didn't cover: sponsor links on lines that mentioned "recipe" much earlier, and blog category pages. Those real lines became new tests in lib/recipes/links.test.ts, and the fix was checked by rerunning the whole playlist (49 of 86 videos correctly found a recipe link).

On another project: whenever a rule decides something from messy input (parsing, matching, filtering), run it over a real sample before trusting it, and turn every surprise into a test.

Run it again

npm install once, then npm run dev (starts the website and Convex together) and open http://localhost:3000. Keys go in .env.local; .env.example lists their names. Checks: npm test, npm run typecheck, npm run build.
